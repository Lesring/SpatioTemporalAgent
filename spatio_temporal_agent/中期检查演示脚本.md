## 第五部分：错漏案例与改进计划（3 分钟，必讲）

### 已观察到的错漏案例

| 案例 | 现象 | 原因 |
|------|------|------|
| 多边形参数传成字符串 | 首次调用 `point_in_polygon` 失败 | 模型把 JSON 数组序列化成字符串 |
| 连续快速调用触发 429 | 请求被限流 | 免费额度速率限制 |

### 改进计划（对齐"业务流程准确率"指标）

1. **参数鲁棒性（已落地 ✅）**：`registry.call_operator` 增加 `_coerce_args`，自动把"字符串形式的 JSON 数组/对象、字符串数字"解析为结构化类型。已验证：多边形以字符串传入也能正确计算，消除了测试 2 中首次调用失败的案例。
2. **参数缺失追问**：模型检测到参数不全时主动向用户追问，而非直接失败
3. **知识库升级**：关键词匹配 → 向量检索（embedding），提升长尾领域词命中
4. **多轮记忆**：支持上下文连续对话（"再算一个"、"把刚才半径改成 8000"）
5. **更多算子**：路径规划、时空叠加、时间范围过滤
6. **限流优化**：请求队列 + 令牌桶，提升并发稳定性（已做 429 指数退避重试）

**收尾：** 评测指标对齐——领域知识库完整度（`knowledge_items.json` 可扩充）、业务流程准确率（本演示已验证"选对算子+提对参数+正确回填"），地理计算准确率题目不要求。

## 常见问题应答

**Q：为什么不用真实 GIS 库（如 Shapely/GeoPandas）？**
A：题目要求"依据基本算子"构建，本项目用纯 Python 实现基本算法（Haversine/射线法/鞋带公式），零重依赖，突出"算子"概念；后续可平滑替换为 Shapely 做精确计算。

**Q：知识库为什么用关键词而非向量？**
A：离线可运行、无额外依赖，作为 RAG 的最小可行版本；改进计划中已列向量检索升级路径。

**Q：如何证明"业务流程准确率"？**
A：`test_llm` 三个场景 = 三次"自然语言→算子选择→参数提取→结果回填"的完整链路验证，可统计命中率；现场交互演示进一步证明泛化。
